# 微信聊天信号 / WechatSignals


**macOS 安装版：[v0.1.0-beta.1 下载](https://github.com/Jelly-RayTian/WechatSignals/releases/tag/v0.1.0-beta.1)** · Apple Silicon · 系统目标 macOS 14+。独立运行，无需 Node.js。此测试版未公证，首次打开说明与限制见 [安装说明](packaging/INSTALL-zh.md)。

macOS 本地优先、只读、单聊分析客户端。本机真实单聊读取和本地语音转写已验证；官方 Jev 在线请求仍须用户主动确认，尚未用真实聊天验证。

## 启动

当前交付已安装 npm 依赖、编译 Keychain helper，并包含核验过的 GreenBubbles 0.10.0 读取二进制。

```sh
npm ci
npm run build:keychain
npm start
```

在本目录运行。依赖 Node.js 22+、Apple Silicon、macOS 14+。编译钥匙串组件需要 Xcode Command Line Tools。安装 npm 依赖和 Electron 下载仅发生在开发安装阶段；应用没有遥测或自动更新；后台语音识别仅在本机运行，Jev 分析仍需手动确认。

默认读取 `vendor/greenbubbles/greenbubbles`。替换读取程序可设置 `GREENBUBBLES_BIN` 为绝对路径，UI 不包含任何命令。新适配器只需实现 `WechatReader`。当前缓存绑定单个微信数据源：账号/数据源改变会拒绝读取，跨重启也保持绑定；下一阶段应增加账号数据库分区。

## 首次微信读取

GreenBubbles 需要本机微信数据库配置和账号密钥。参考 [官方设置指南](https://github.com/bojieli/greenbubbles/blob/main/docs/PASSPHRASE_ACQUISITION.md)。其密钥获取流程需要管理员权限、重签微信和重新登录。应用不自动执行重签或捕获。首次连接助手只在本机终端中明确输入 CONNECT、并完成管理员授权后执行重签和捕获。日常读取只读，不修改微信数据库。当前捆绑查询二进制和首次授权所需的 acquire helper；没有发送 helper。客户端内点击“连接本机微信”可检测现有配置，并打开本机授权助手。

注意：GreenBubbles 的微信数据库密钥由上游工具管理，其默认位置是本机受权限保护的文件。它与本应用的 TypeSafe API Key 是两种不同凭据。本应用 TypeSafe Key 只进入 macOS Keychain，不进入 SQLite 或配置。

## 分析工作流

1. 重新检测，等待数据源可读。
2. 选择单聊，按最近 7 / 30 / 90 天、自定义日期或全部本机历史读取。每页最多 500 条，显示条数、页数和覆盖状态。每轮 5 万条保护上限会明确提示继续读取，不会假装完成。
3. 输入官方 TypeSafe API Key，保存到钥匙串；Renderer 不会取回 Key。
4. 范围读完后点击分析，检查全部匿名化分段与请求次数，再点击“确认发送全部分段并分析”。
5. 仅此步骤向官方 `https://api.typesafe.ai/v1/systemone` 发送请求。按保守的 12,000 UTF-8 字节预算分批请求，每批独立评估，并非一次全历史推理。响应验证后保存 SQLite；失败或停止保留成功分段并明确标记部分结果。

用五级 `Score` 量表获得 0–4 的加权位置，再乘 25 换算成 0–100 行为信号分。各段官方 confidence 独立保存；旧版汇总按文本条数加权，证据版汇总取可评价分段中位数，整段 confidence 不合成。分数不是喜欢概率，五个维度也未经心理测量学验证。

仅发送纯文本中的 `speaker`（Me / Person A）和清理后的正文；不发送会话/消息 ID、昵称元数据、头像、时间戳、附件/XML或数据库路径。所有已知联系人标识、本应用识别的联系方式、链接和路径会替换。规则无法穷尽自由文本中的人名或间接身份信息，预览是必要的发送前检查；发现残留请取消，不应视为形式化匿名化保证。每条文本最多发送 2000 字符。

## 本地数据

本地统计使用全部已读范围，聊天列表为流畅显示只展示最后 300 条。图表包括日/周/月聊天频率、双方消息数量和占比、开启对话次数、回复时间分布、24 小时活跃时段。Jev 分段信号走势来自实际保存结果，尚未分析时不生成假分数。

微信可读、范围读完、Jev 分析完成是三个独立状态。打开助手或进程退出不代表连接成功。读取失败或停止显示部分数据，并禁止完整范围分析。任务进度和分页游标只存在当前运行内存，重启后需重新读取；已缓存记录和分析仍留在 SQLite。

SQLite 位于 Electron `userData/store/signals.sqlite`，通常为 `~/Library/Application Support/wechat-signals/store/signals.sqlite`。目录 0700、数据库 0600。缓存联系人、会话、当前聊天样本、分析结果；原微信数据库不变。当前缓存供本机持久化，UI 尚未提供离线缓存浏览和清除面板。SQLite 未额外加密，应结合 macOS FileVault 使用；凭据不在数据库中。

Keychain service: `local.wechat-signals.typesafe`，account: `api-key`，使用 Security.framework。Key 通过 stdin 传给 Swift helper，不作为命令行参数。首次访问可能出现系统钥匙串授权提示。

## 内部读取插件与零导入连接

内部插件 `GreenBubblesPlugin` 实现 `WechatReaderPlugin`，持有抽象 `WechatReader` 和只读连接预检。UI 调用 `ApplicationService.connection()`，不接触具体命令；首次连接助手由主进程打开固定路径，Renderer 不能传入命令或路径。

点击“连接本机微信”查看六项本地检测，点击“打开首次连接助手”打开终端。首次流程需要明确输入 CONNECT 才会重签微信，再由本人输入 sudo 密码，并手动重启微信、退出账号和重新登录。助手获取数据库密钥、限制本机文件权限并验证可读性。不会自动终止微信、覆盖已有密钥、导入聊天或触发 Jev 请求。

日常打开应用直接读取本机微信；不需要重复导出或导入。微信升级、密钥失效或数据库格式变化时仍可能需要重新诊断。

## 顶部设置与本地语音转写

右上角固定「设置」打开弹窗：输入官方 TypeSafe API Key，保存到 macOS 钥匙串，并选择 jev-latest 或固定官方 jev-1.13.0。联系人列表下不再放 Key 输入；联系人、聊天、结果面板各自滚动。模型名称保存在 SQLite，Key 不在 SQLite 中。

聊天面板按类型显示语音、表情贴图、图片、视频、引用等，不再统一显示“未完整解码”。内容覆盖显示可读文字、语音总数/已转写数和贴图数量。内置文字表情仍作为原正文读取；自定义贴图目前不识别画面含义。

启动后默认以 20 路后台处理已读取并缓存的单聊语音，新读取的缓存也会加入队列。后台不调用 Jev；设置中可关闭自动转写或调整 2/4/6/8/12/16/20 路及 Base/Small 模式。暂停后台后，顶部「语音转文字」可手动批量处理所选范围待转写语音；「用 Jev 判断」打开匿名化预览，再次确认发送才调用 Jev。无需等待全部语音转写，未转写内容会在预览中统计排除。已缓存的转写不会重复处理。音频通过 WechatReader 抽象提取，GreenBubbles 适配器使用真实 attachment inspect/materialize 协议；SILK 经 FFmpeg 转码，whisper.cpp 多语言 small q5_1 在本机运行。临时音频与输出文件位于 0700 私有目录，操作结束后清理。不会调用 Qwen、Ollama 或外部语音 API。

转写结果保存 SQLite，重新读取时复用；可点「检查 / 编辑文字」修正。自动语音转写可能漏字、误识别或产生幻觉，匿名化预览中标记来源与可能误差。只有显式确认分析时才发送清理后的转写文本；没有转写的语音、贴图及图片不做语义推断。模型安装需要约 181 MiB 权重，当前已捆绑本机 arm64 二进制和权重。参见 vendor/speech/NOTICE.md。

Jev 设置提供「打开 Jev 官网」「配置 Key / 购买额度」按钮，在系统浏览器打开 TypeSafe 官方网站/控制台。登录和购买在官网完成，获得官方 Key 后回应用保存到钥匙串。

转写性能：主进程复用微信数据目录检测结果 5 分钟，提取失败会重新检测；每条语音仍校验其来源和消息绑定。默认最多20条语音同时在本机处理，可选 2/4/6/8/12/16/20 条并行，已成功转写的不重跑，停止会等待在途处理结束。首次模型启动可能比后续慢，耗时随语音长度与机器负载变化。

转写模式在设置中选择：快速 Base（默认）与精细 Small（较慢）。较小的 Base 模型省时，但识别准确度可能下降，可检查并编辑转写。启动后台转写可在设置中关闭；Jev 判断始终需要手动点击并确认。

转写进度按读取、转码、识别、空文本、保存等阶段分类失败，缺失本机音频单列为未完成。请先在微信播放或下载相应语音，再手动重试。缺失音频不会重新扫描数据库目录，也不会启动识别；单条消息显示当次失败原因。并发数量按任务固定，每个识别进程线程数按设备核心数与并发数分配。

桌面「微信语音转写」存放每条已完成转写的 TXT 副本，启动时补存已有 SQLite 转写，新完成与应用内编辑自动同步。文件名由稳定消息标识的哈希生成，避免重开产生重复；桌面副本被删除可从 SQLite 恢复，不需要再次识别。目录 0700、TXT 0600。导出失败不会删除 SQLite 文字；点击「打开桌面转写文件夹」可补存并打开目录。SQLite 是自动复用转写的主缓存，桌面 TXT 是可查看副本。

缺失音频只能在取到音频后识别；当前 GreenBubbles voice lookup 查询本机媒体数据库，没有自动从微信下载缺失音频的接口。请在微信中播放/下载后再手动重试；不会制造空音频的转写内容。

## 当前设置与评分（2026-10-08）

顶部「设置」提供「转写与缓存」「Jev 与 Key」「评分标准」三个页签，设置保存 SQLite；API Key 仍仅存 Keychain。默认启动后台本机识别，最大 20 条同时在途。队列只使用已缓存且当前数据源已验证的单聊消息；先加载联系人，再识别。成功的语音跳过，失败或音频缺失本轮不循环重试；关闭后再打开会重新检查尚无文字的语音。可暂停后台后手动重试。后台独立于读取与 Jev，浏览可继续，分析预览采用当时的文本快照；预览生成后新增转写不混入已确认的请求。

所有成功文字同时保存在 SQLite 和桌面「微信语音转写」，缺失副本从 SQLite 重建，不重新识别。没有原始音频无法识别；需本人在微信播放或下载后重试，当前读取工具无自动下载接口。20 路不保证更快，尤其 GPU/内存竞争；Small 较慢且也可能出错。

behavior-v3-evidence 为五个指标分别定义等级，明确说话者归属、上下文、反证、礼貌/事务行为、拒绝边界与识别歧义。每段一次官方请求包含5个Score和15个Choice，分别选择支持、反证和可评价程度；证据由应用从已发送的匿名正文定位，不让模型生成引用。历史汇总取质量充分分段的中位数，旧加权结果保留并标注旧版。新增评价报告、回复中位数、P90、样本数和7×24热图。尚无标注样本准确率评测，不能宣称已保证判断准确。详见[算法参考与评价方法](docs/ACCURACY_RESEARCH.md)。

30个合成案例的官方实测匹配51/53个行为标签，保留集22/24；不是实际聊天准确率。程序59项测试通过。评价报告可本地校对行为标签，SQLite持久化，原评分不改、校对不上传。研究方法、真实测试报告和未通过案例详见[评价修复与验证](docs/EVALUATION.md)。


### v7 信号事件汇总

好感与暧昧分开显示表达强度、片段出现频率和独立交流次数。普通闲聊与一般关心不再稀释明确浪漫表达；委婉/低置信表达单独标为待复核。已有完整行为判断的结果在本机重新汇总，不重新请求 Jev、不改原始记录。详见 [v7 计算规则与限制](docs/EVALUATION_V7.md)。

### 客观性审计与冻结规则

当前好感、暧昧指数仍是未经独立校准的实验性描述。已比较 WechatVibe 的时间加权、SignalLens 的信息量加权与本程序的事件汇总，未发现足以证明当前或替代算法完全准确的依据。评分源码与作者案例已冻结，`npm run audit:scoring` 可离线检查历史官方输出的概率质量及版本匹配；不发送聊天，不调用 API。详见 [评分客观性审计](docs/OBJECTIVITY_AUDIT.md)。

默认同时展示全部五项评价，新增“关系走向”页解释当前好感强度，并按已保存 Jev 行为提供四种条件情景、反证和可点击依据。没有未来概率或结局保证，不新增请求。v8 提示词明确区分前任/第三人、引用辱骂与真正针对自己的浪漫或拒绝；旧结果需手动重新分析才能应用新版归属规则。数值公式保持不变。详见 [v8 功能、限制与验证](docs/RELATIONSHIP_OUTLOOK.md)。

### v9 对话依据与本机多模态（2026-10-11）

设置已改成独立工作区；评价报告增加覆盖图、双向互动图、可点击信号时间线及跨分段支持/反证索引。点击“定位完整聊天上下文”回查本机消息；旧报告没有消息映射时会明确提示，需手动重新分析生成新映射。

分段优先使用 6 小时会话间隔、30 分钟停顿和轮次边界，保留有限前后文。停顿只是话题边界启发式，不是语义话题识别；每条目标消息只计一次。Jev 增加邀请、情绪支持、亲近表达三个双向题，每段默认 25 题，换序复核 37 题。双向结果不混入五项分数，缺少回复不等于拒绝。

“本机观察图片”使用 Apple Vision OCR、有限粗分类、条码数量与帧覆盖，不增加外部模型/API；复杂场景、表情包寓意和心理不能可靠识别。多帧仅处理第一帧，粗标签只在本地展示；只有来源标记后的匿名文字可能进入经用户确认的 Jev 请求。图片和语音文字可手动校正，成功缓存继续复用；旧图片观察通过独立升级按钮更新，已人工核对的缓存不被覆盖。

48 个作者编写案例及外部独立数据评测工具已就绪，尚无 v9 独立盲测准确率。见 [v9 设计与限制](docs/UPGRADE_V9.md) 和 [评测说明](docs/EVALUATION.md)。

### 完整范围检索与报告状态（2026-10-22）

「聊天记录」现在可以检索完整已读范围，包含正文、已有转写和图片 OCR，不再只浏览最新 300 条。可组合发送者/类型筛选，每页 50 条；⌘F 聚焦搜索，Escape 清空。报告首屏显示保存范围、生成时间及待复核维度，区分旧报告与当前读取。检索与分页只在本机完成，不触发 Jev。详见 [使用与边界](docs/LOCAL_SEARCH.md)。
