# 评分客观性审计与开源方法比较

日期：2026-10-09。结论：目前无法证明哪一种聊天汇总方法更接近真实好感，更不能保证完全准确。本轮冻结现有实验性规则，补全评估和来源说明，不再凭用户觉得分数偏高或偏低修改权重。

## 已核对的原始实现

| 来源 | 核对内容 | 能借鉴什么 | 不能据此声称什么 |
| --- | --- | --- | --- |
| [WechatVibe scoring.ts](https://github.com/tswawa/WechatVibe/blob/main/electron/laya/scoring.ts) | 对方逐条关系分类分布映射为分数，按新旧消息赋予线性时间权重后求均值。源码将 affinity 标为娱乐性指数。 | 对方/自己分开；评分固定且同输入不叠加历史分。 | 中性 50 是约定，不是心理基准；该实现没有为本客户端的 Jev 指标提供验证。 |
| [SignalLens scoring.py](https://github.com/xinian5216/chat-signal-analyzer/blob/main/scoring.py) | 用关系信息量与模型 confidence 组成权重，汇总 warmth、engagement、special attention 与浪漫/疏远证据；低信息量单独显示。 | 将可观察信息量和强度区分，低信息量回复不应简单当作拒绝。 | 权重、阈值也是设计选择；模型 confidence 不是经本任务校准的正确率，不能把这种加权当科学定论。 |
| [ChatLab](https://github.com/ChatLab/ChatLab) | README 的本地 SQL、标准化数据、统计可视化和工具调用架构。未将其当作浪漫评分算法。 | 客观统计与 AI 解读分开，保持数据可追溯。 | 大量图表不等于真实心理测量。该项目为 AGPL-3.0，本轮不复制代码。 |

以上仅阅读和独立评估方法，本轮没有引入其他模型，也没有复制上述实现。当前评分仍由官方 Jev 的行为判断与本地规则构成。

## 当前方法的偏差审计

- 全片段中位数：明确表达很少时会低估表达强度；适合描述典型片段，不适合代表最强表达。
- 当前 v7 事件峰值中位数：可描述被选中事件的强度，但有选择偏差，可能放大孤立表达。不同分段容量也影响峰值和片段频率。
- 信息量/置信度加权均值：依赖信息量判断及置信度质量，错误的高置信片段可能支配结果。
- 时间加权均值：更偏重近期，不能证明近期更能代表真实心理。
- 具体关心、信任、积极情绪、频繁回复、表情和语音数量都不等于浪漫兴趣。浪漫、友好、事务和边界须分别检查。
- 0/25/75/100、0.8 折扣、6 小时会话边界、0.6 confidence 门槛和评分上限均为未校准的产品规则。确定性只能保证公式可重复，不保证模型正确或构念有效。

本轮没有再改变 v7 权重或分段公式。报告保留全部片段中位数与事件条件强度，明确两者描述的对象不同。旧报告的本机重算不是一次新的模型判断。

## 已实施的约束

`evaluation/frozen-profile.json` 保存当前行为定义、提示词构造、证据选择、匿名化、分段/汇总、作者构造案例及评测器的 SHA-256。测试发现漂移会失败。冻结的是实验性版本，不是认证；不可仅为使测试通过而刷新摘要。后续需新版本、变更理由和预先指定评估，再比较结果。

报告和设置显示“实验性行为指数”“尚未独立盲测与校准”。没有把用户反馈写进 Jev state，也没有通过用户期望的分数校正结果。

`npm run audit:scoring` 仅读取已有的作者构造合成报告，不打开微信数据库、Keychain或网络，不改写原报告。输出到 `evaluation/results/calibration-audit.json`。

新增评测：

- 多分类 Brier 分数（五类平方误差求和，范围 0–2，越低越好）。
- 对数损失（越低越好，目标概率下限 1e-15）。
- 选中类别概率的五箱可靠性统计和 ECE；小样本的 ECE 不可作为通过门槛。
- 精确参考标签、排除多值参考标签、缺失/非法分布与有效覆盖率均单独报告。
- 原有误报、漏报、分类混淆和选项换序一致性保留。

这些评测的目标是**作者标注的可观察行为等级**，不是好感概率。概率分布仅在全部五类合法且总和与 1 的偏差不超过 0.03 时归一化后评价；多值标签不伪造成唯一真值。无法评价与未调用也不计作完美预测。

方法依据：[scikit-learn 官方概率校准文档](https://scikit-learn.org/stable/modules/calibration.html)区分概率输出与校准，并要求独立数据；[TypeSafe 官方 confidence 文档](https://docs.typesafe.ai/confidence)说明官方字段含义。新增了评估工具，不表示已经完成拟合校准。

## 本次实际验证与未完成的证据

现有结果是 `behavior-v4-observations`，30 个作者构造案例，原报告声明 `independentAnnotation: false`。能用于多分类适当评分的唯一参考标签为 29 项；其他允许多个等级的标签只参与原有匹配评估。离线审计计算 Brier ≈ 0.06677、对数损失 ≈ 0.13530，有效概率覆盖 29/29。这些是旧版合成数据的诊断，不能当作 v7 准确率、真实关系准确率或推广效果。已有保留集被反复查看，不能再称为新盲测集。

当前 v7 没有对应的独立关系标签、冻结后的新盲测、中文单聊泛化验证或整体指数校准。因此状态明确保持 `experimental-unvalidated`，不因程序测试通过升级。

## 后续算法升级的最低证据要求

1. 预先定义可观察目标：是否出现对方指向自己的具体关心、个性化赞美、明确浪漫表达、关系边界；主观真实心理单独处理，不能拿作者猜测当真值。
2. 在看模型结果之前冻结新测试集；至少两名独立标注者按同一操作定义标注，并记录分歧及一致性。分歧不是简单服从作者意见。
3. 同一联系人/同一会话不得跨训练、校准和测试集，避免内容泄漏；合成与真实样本分别报告，方言、反讽、引用、语音错误和缺失媒体分别评估。
4. 比较中位数、信息量加权、时间加权和事件汇总时使用同一冻结输入、同一目标、同一测试划分；记录漏报、误报、拒判和置信区间，不以分数变高作为改善标准。
5. 对置信度做校准只能使用独立校准集，不能在最终测试集上调参。若无独立心理标签，就不发布心理预测准确率。
6. 任何真实聊天上传仍需用户在应用内主动预览确认；本轮研究和离线审计未发送私人聊天，也未发起新的 Jev 请求。
