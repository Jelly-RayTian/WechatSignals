# 数据源标识变化后的连接恢复

2026-11-02 修复：底层 GreenBubbles 仍可查询，而旧 SQLite 缓存绑定的数据源标识与当前不同，曾被笼统显示为读取失败。不能仅凭微信版本变化就断言是升级导致，也不能据此把两个数据源当作同一账号合并。

启动时先只读取得 source status 的标识，再只读检查旧库绑定。标识一致时沿用默认库；标识不同时使用 store/sources/SHA256(identity)/signals.sqlite，并保留旧库。转写副本同样使用隔离目录。标识不可用时不猜测、不迁移、不重绑。原有运行中账号切换保护继续保留，并明确提示重启。

旧记录和分析不会自动迁入新数据源，避免账号或记录混合。Keychain 服务不变。已知旧缓存不会被删除、重签微信或覆盖数据库密钥。首次探测失败仍需检查真实权限/密钥/兼容性问题，不能将所有连接问题视为此情况。

验证：旧库字节保持不变、同源路径复用、异源路径稳定隔离、独立库绑定继续拒绝错误来源、错误提示不暴露身份标识；完整 125 项测试、类型检查和构建通过，实际窗口恢复联系人列表。本次未调用 Jev。
