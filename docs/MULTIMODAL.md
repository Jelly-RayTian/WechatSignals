# 多模态证据版 v6

2026-10-09。目标是减少丢弃附件导致的上下文断裂，让每项判断能追溯输入来源；没有声称已提高真实关系判断准确率。

## 官方边界与方案

当前官方 Jev 1.13 仅接受文本，不接受图片、音频、视频：[模型说明](https://docs.typesafe.ai/models)、[State](https://docs.typesafe.ai/concepts/state)、[OpenAPI](https://api.typesafe.ai/openapi.json)。因此使用本机预处理，再向官方 Jev 发送匿名文本和来源标记。没有替换模型，没有使用本地 Qwen，没有新增云端视觉或转写服务。

GreenBubbles 当前随附 CLI 的 `attachment --help` 和源码 `docs/ARCHITECTURE.md` 确认支持精确消息绑定的 `attachment inspect/materialize ... --kind image`。复用这一接口，不访问 UI、不自动发送微信消息、不修改微信数据库。

## 使用

1. 选择单聊并读完日期范围。
2. 语音按原有设置在本机转写。点击“本机识别图片文字”处理范围内未处理图片，4 路并行；再次点击只补未处理及失败项。缓存命中直接复用。
3. 在聊天记录检查图片 OCR 和语音文字。无字照片、贴图画面、视频及音色情绪尚不识别，明确显示未知。
4. 点击“用 Jev 判断”，检查匿名预览，再确认发送。准备媒体或打开聊天不会自动调用 Jev。旧报告保持历史结果，需要手动重新分析才能包含新证据。

## 数据与判断

- Apple Vision 本机 OCR，中文简繁和英文，低于 0.5 的 OCR 行不进入结果；该值是识别器置信度，不是心理判断准确率。
- OCR 标明“图片内文字，不是发送者陈述”，不能把截图里的告白归给图片发送者。必须结合相邻明确回应判断归属。
- 保留语音、图片、贴图、视频的顺序与缺失标记；缺失内容不作为拒绝或冷淡。附件占位本身不能启动分析。
- Unicode 文字表情保留在文本中；不推断未知贴图含义，也不按爱心、自拍或附件数量自动加分。
- 相同匿名规则处理原文本、语音转写和 OCR；只允许匿名说话者、正文、来源类型和内容可用状态进入请求，禁止原始附件、路径、联系人 ID、昵称和头像元数据。自由文本身份信息仍需用户预览核对。
- SQLite 新增 `media_observations` 表，沿用单账号来源绑定和私有文件权限。原图仅存在本次 OCR 的私有临时目录，处理后清理，不加入桌面转写文件夹，不上传。
- 本次分析报告展示文字、语音、图片、贴图来源数量及未知内容数量。来源数量不是好感指标。
- 分段预览预先检查包含所有问题与可选复核的完整请求容量，必要时缩小分段，保留顺序和少量前文。
